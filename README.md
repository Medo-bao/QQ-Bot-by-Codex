# QQ Bot

从 [tencent-connect/dsh-qqbot](https://github.com/tencent-connect/dsh-qqbot) 的 `main` 分支改造的本地 Codex 插件。
上游基线：`ee980be`（2026-10-28，0.5.4）；本插件版本：0.0.2。

QQ 私聊或群聊 → 腾讯 QQ Bot SDK → 本地 Codex App Server → QQ 回复。
使用本机 Codex 的登录、模型提供商和工具配置。

## 功能

- 完整 MCP App 设置页，注册左侧栏全局入口与聊天侧面板入口；也可在本机浏览器打开同一页面。
- 扫码或手动绑定机器人，凭据保存在本机，独立的浏览器设置页。
- 每个 QQ 私聊用户、每个群独立的持久化 Codex 会话，进程重启后恢复上下文。
- 私聊流式回复，群聊 Markdown 分段回复；群聊默认需要 @机器人。
- 图片作为 Codex 图片输入；其他附件下载后以本地路径交给 Codex；转发 QQ 提供的语音转录。
- 将生成文件发送回当前 QQ 会话；模型有 `qqbot_send_file` 和 `qqbot_ask_question` 工具。
- Codex 命令、文件、权限审批与追问，通过 QQ 按钮或文字作答；仅该任务发起者可以回答。
- 插件内的 MCP 工具可查看状态、设置配置和发送用户指定的消息或文件。
- 模型提供商切换、会话预设、技能注入、独立视觉模型与多选追问。
- 共享后台进程，多个 Codex 聊天共用连接。关闭某个聊天不会断开 QQ。
- 默认随 Codex 加载插件自动连接已绑定的 QQ Bot；可在「运行设置」关闭自动启动。状态刷新不会重启手动停止的连接。
- OpenAI 模型默认使用 HTTP 流式连接，避免 WebSocket 连续超时重试导致长时间等待首条回复；可在「运行设置」切回自动选择，自定义提供商保留原连接配置。

## 环境

- Node.js >= 20.3.0。
- 已安装并登录的 Codex CLI，需要 `codex app-server`（本次开发使用 0.147.0）。
- QQ 手机客户端用于扫码；或者已有 QQ Bot AppID / AppSecret。

Windows 会优先使用 PATH 中的 `codex.exe`，或 npm 全局安装的 `@openai/codex/bin/codex.js`。
找不到时在配置中指定 `codexCommand` 的绝对路径，支持可执行文件和 `.js` 入口。

## 安装到 Codex

获取源码并在仓库目录运行：

```powershell
git clone https://github.com/Medo-bao/QQ-Bot-by-Codex.git
cd QQ-Bot-by-Codex
npm.cmd ci --ignore-scripts
.\scripts\install.ps1
```

安装脚本会构建、生成 `release/codex-qqbot`，注册本地市场 `qqbot-local`，安装 `codex-qqbot`。
安装生成的插件仅注册到本机 Codex，不会发布到公共插件目录。

然后重新打开 Codex 或新建聊天，选择「QQ Bot」，输入：

> 设置 QQ Bot 并连接到 Codex

支持 MCP Apps 扩展入口的客户端会提供「QQ Bot」侧栏应用和聊天侧面板入口。
`qqbot_setup` 也可以在聊天中打开设置，并返回本地页面链接，供不呈现 MCP App 的客户端使用。
本插件通过官方 `openai/ui.entrypoints` 协议注册入口，不修改 Codex 桌面程序文件。

界面采用「会话 / 设置」顶部标签，机器人和会话合并为可折叠的侧栏分组，同一机器人的私聊与群聊缩进排列在组内，与 Codex 项目会话列表保持一致。
分组右侧「…」保留机器人连接与绑定入口。折叠状态会保留，搜索可以展开匹配会话，当前聊天不会因收起分组而关闭。
侧栏宽度为 240px。会话名称和操作按钮集中在顶部工具栏，模型、权限及存储路径收进独立的「会话设置」窗口，聊天记录占据其余空间。「直接发送」打开独立弹窗，可选择接收会话，以 QQ Bot 身份发送原文、图片或其他文件，不调用 AI；会话底部输入框继续使用共享 AI 会话。
文件可通过选择、拖入或粘贴添加；一次选多时保留上限内的有效文件，单独提示空文件、超大文件和超出数量的部分。

直接发送支持文件预览、移除、分会话保留草稿及上传进度，可只发文件，也可同时发送文字。文件按图片、视频、语音或普通文件类型发送，保留原文件名并存入所选会话的 `files/direct` 目录。部分发送失败时保留未成功的内容，重试不会重复发送已成功的项目。数量与大小遵循「图片与文件」设置。

附件可通过选择、拖拽文件或粘贴图片加入，重复选择相同文件会合并。会话输入框随内容增长；发送等待期间继续输入的新草稿会保留。设置保存中显示进度，弹窗内直接显示失败原因，保存期间的新修改也会保留。顶部显示回复、等待回答和排队状态，断线重连时同步更新连接提示。
原有绑定、访问范围、模型预设、提示词、媒体、运行设置和会话管理入口均保留。
可扫码/手动绑定、查看和登录本机 Codex、编辑全部配置、添加预设，以及中止/压缩/重置会话。

也可以手动执行：

```powershell
npm.cmd run build
npm.cmd run package:plugin
codex.cmd plugin marketplace add (Resolve-Path .).Path
codex.cmd plugin add codex-qqbot@qqbot-local
codex.cmd plugin list
```

插件使用标准根目录 `plugin.json`、`mcp.json` 和 `skills/`。发行目录包含已打包的 JavaScript；运行时不需要 DSH 或此仓库的 node_modules。

更新源码后重新构建、打包，再按本机 Codex 支持的市场更新和安装命令刷新插件；旧后台进程需先 `shutdown` 后再启动。

## 绑定与使用

1. 在 Codex 中运行设置流程，打开 `qqbot_setup` 返回的本地页面；也可运行 `node dist/cli.js setup` 获取页面地址。
2. 输入工作目录，选择手机 QQ 扫码，或手动填写 AppID / AppSecret。绑定成功后启动 QQ 连接；之后 Codex 加载插件时默认自动连接，无需再次扫码或手动启动。
3. 默认私聊仅接受白名单，群聊关闭。先给机器人发一条消息，在设置页「最近消息来源」中找到用户 OpenID，填入允许用户并保存。
4. 群聊需要开启群访问、允许对应群，并允许任务发起者；默认还需要 @机器人。
5. 在 QQ 中发起任务。若 Codex 请求审批或补充信息，点击按钮，或按照提示回复 `/answer 请求编号 答案`。

QQ 中的会话各自独立；插件不会把 QQ 消息插入当前桌面聊天。Codex 的登录与配置由本地 App Server 读取。
每个新线程会禁用自己的 QQ 管理插件，避免再次建立 QQ 连接；原有其他插件和工具配置继续由 Codex 加载。

### QQ 命令

| 命令 | 用途 |
| --- | --- |
| `/new`、`/reset`、`/clear` | 新建会话，清空当前 QQ 会话的上下文映射 |
| `/compact` | 压缩会话历史 |
| `/model`、`/model 模型名称` | 查看或切换账户可用模型 |
| `/model 提供商/模型`、`/model reset` | 使用已配置的模型提供商，或恢复部署默认 |
| `/preset`、`/preset 预设ID`、`/preset reset` | 查看或切换预设，新会话生效 |
| `/effort`、`/effort high` | 查看或切换当前模型支持的推理强度 |
| `/stop` | 中止任务并取消排队任务 |
| `/bot-status` | 线程、队列与用户/群 OpenID |
| `/bot-ping`、`/bot-version`、`/bot-help` | 连通检查、版本和帮助 |
| `/answer 请求编号 答案` | 回答待办问题或审批 |

### 本地命令

```powershell
node dist/cli.js setup
node dist/cli.js start
node dist/cli.js status
node dist/cli.js models
node dist/cli.js stop
node dist/cli.js shutdown
```

`stop` 停止 QQ 与 Codex 工作进程；`shutdown` 还会关闭设置页与共享后台进程。

## 配置与数据

默认数据目录：`$CODEX_HOME/qqbot`（通常为 `~/.codex/qqbot`），插件、命令行和浏览器入口共用。
显式设置 `QQBOT_DATA_DIR` 可以选定其他固定位置，优先级最高。

- `config.json`：QQ 凭据和运行设置。
- `sessions.json`：按机器人 AppID、私聊/群和 OpenID 存储的 Codex 线程映射与模型偏好。
- `media/`：收到的附件；默认保留 24 小时。
- `runtime.log`：后台进程日志。

设置页和状态工具不返回 AppSecret。设置页只在本机回环地址监听，访问链接带随机访问令牌。
共享控制通道为本机命名管道（Windows）或当前数据目录下的 Unix socket。

配置示例：

```json
{
  "cwd": "E:\\MyProject",
  "model": "",
  "approvalPolicy": "on-request",
  "sandbox": "workspace-write",
  "streaming": true,
  "requireMention": true,
  "access": {
    "c2cMode": "allowlist",
    "c2cAllow": ["用户 OpenID"],
    "groupMode": "allowlist",
    "groupAllow": ["群 OpenID"]
  }
}
```

其他配置见 `src/config.ts`：额外提示词、队列数量、超时、媒体大小、文件发送白名单。
文件默认允许来自工作目录、媒体目录、当前会话的 `generated_images/<threadId>` 目录与 `sendFile.extraRoots`；其他会话的生成目录不会自动放行。校验实际路径，符号链接不能绕过白名单。
`QQBOT_APPID` / `QQBOT_SECRET`、`QQBOT_CWD`、`QQBOT_CODEX_COMMAND` 可以覆盖对应配置。
不要在聊天中粘贴 AppSecret，使用本地设置页或本机配置文件。

图片理解默认使用对话模型；可在「图片与文件」设置独立的 Codex 视觉模型提供商与模型，使用 `qqbot_describe_image` 分析图片。
图片、视频、语音和普通文件发送分别使用腾讯 SDK 对应通道；音视频内容的进一步解析使用 Codex 可用工具。
文件发送与图片理解均接受绝对路径、本地 `file:` 链接和 `sandbox:` 文件引用，仍按实际路径校验目录。单轮内同一文件通过工具与回复链接交付时仅发送一次；工具失败提示包含具体原因。

`storageDir` 设置会话与资源的归档目录，可在「图片与文件」修改；留空时使用本机数据目录下的 `storage`。归档与任务工作目录分开，结构为：

```text
storage/
  bot-<AppID>/
    private 或 group/
      peer-<OpenID>/
        session.json             会话名称与当前、上一条线程 ID
        history/<threadId>.md     可直接阅读的聊天记录
        history/<threadId>.json   消息与发言人数据
        attachments/             接收到的附件
        files/<threadId>/        新生成的文档和导出文件
          images/                原生图片生成结果
```

目录使用稳定 ID，重命名会话不移动文件。启动时回填现有线程的聊天记录，之后每轮更新；旧上下文保留各自的历史文件。原生生成图片通过目录关联保存到会话的 `images`，已有图片迁入后原路径仍可访问，后续生成不额外复制。收到的附件继续遵循附件保留时间，聊天归档和生成文件长期保存。
原生 Codex 上下文仍由 QQ Bot 的独立 `codex-home` 管理，聊天记录归档用于阅读和备份。插件凭据及运行配置保存在原本机数据目录。项目的已有工作文件保留原位置，新任务会收到本会话的输出目录。存储目录不会进入 Git 或插件安装包。

预设可配置名称、模型、提供商、推理强度、工作目录、额外提示词、技能名称和 Codex 会话配置覆盖。
QQ 中 `/preset` 选择的预设在 `/new` 后生效；已经存在的线程保留其正在使用的预设。
独立视觉分析以只读临时 Codex 会话执行，输出按配置的字符数截断，不使用额外的 OpenAI API 客户端。

在「会话」中选中私聊或群聊，可独立配置模型、提供商、推理强度、预设、工作目录与角色提示词。
右侧显示真实聊天记录，插件页面铺满可用高度，侧栏与底部输入区贴齐页面底部。底部输入框可直接继续对话，支持 Enter 发送、Shift+Enter 换行。本机发送的消息继续该 QQ 会话的同一段 AI 上下文，生成的回复同步到 QQ。切换会话保留各自草稿，发送成功后清空输入框。
切换会话或临时查看全局设置时，保留各自的历史阅读位置和工具详情展开状态；发送后可继续在输入框编辑，不打断已经移到其他控件的操作。搜索框支持 Enter 打开首个结果、上下方向键选取结果和 Esc 清空，悬停会话可查看完整名称。
点击会话标题旁的铅笔可重命名，名称会用于列表、标题和搜索，并在重启后保留；留空恢复默认名称。
点击右上角「会话设置」打开独立弹窗。新会话默认勾选「跟随全局设置」，也可恢复全局；关闭后才能设置本会话覆盖项。
关闭弹窗或按 Esc 会暂存本页未保存的会话设置，下次打开可继续编辑；「放弃修改」才会丢弃这些修改。未提交的无效会话设置不影响全局设置保存。
历史记录按需分页读取，提问和操作确认可直接在会话窗口回答。
会话显示采用 Codex 的蓝色用户气泡、正文 Markdown 和可折叠的「活动」记录；支持表格、代码复制、回复复制、图片预览和回到最新消息。群聊保留成员身份和回复对象，界面整理原始 @标记。
会话设置可独立选择执行范围、操作确认、命令联网与网页搜索，默认跟随全局。保存后下一轮生效，保持原线程上下文；「恢复全局设置」会同时清除这些覆盖项。原生命令仍由 Codex 执行相应权限策略。
全局和会话设置均提供「请求批准」「帮我批准」「完全访问权限」选择。「帮我批准」使用 Codex 原生自动审批；「完全访问权限」同时启用本机文件与联网访问，并设置为不请求批准，后续文件、命令和权限申请不会再次向 QQ 用户提问。普通信息补充和账号登录仍按原流程处理。只读、网页搜索等细项保留在自定义权限中。
网页搜索与命令下载分别受搜索模式和联网开关控制。Windows 沙箱中 PowerShell 的 HTTPS 下载可能出现 TLS 身份验证错误；本插件提供 `node dist/cli.js download <URL> <绝对输出目录> [上限MB]`，使用 Node HTTPS 下载并校验正常证书，受原生命令的网络与写入权限限制，不会自动发送文件。每轮任务会提供下载命令与本会话的输出目录。
「显示工具执行结果」关闭时，中间工具成功、失败和重试仅保留在本地活动记录；开启后才同步到 QQ。最终任务失败仍会给出简短提示，QQ 通道发送失败会显示在本机会话中，不会通过同一失败通道循环发送错误。
群聊成员共享本群 AI 上下文，每条消息附带发言人昵称与稳定用户 ID，界面同时显示回复对象；QQ 中的文字回复自动 @本轮发起者。本机直接发起的群聊任务不沿用上一位 QQ 成员的 @对象。
每次提交回复任务前，先读取本群已接收的完整前文，再放入当前发言人的问题；群聊历史只由本插件补入一次，不重复附带 SDK 的截断历史。未 @的已授权消息和群内追问回答也会留作前文，仍仅在 @机器人时启动回复任务。
群聊接收到的完整消息和机器人回复保存在本群的 `group-messages.jsonl`，近期上下文保存在 `context.json`。每轮按「每轮补充的群聊历史条数」附带此前完整对话，默认 10 条，不再按 200 字截断；发言人、附件本地路径和原 AI 线程继续保留。允许范围内收到的未 @消息也会记录，仍仅在 @机器人时回复。
首次更新会从本机现有的当前群聊线程回填上下文，重启后台后继续使用；入队消息只读取在它之前收到的群成员消息，以及此前已完成的机器人答复。`/new`、重置上下文或切换角色后开始新的近期上下文，旧记录留在存档。只记录机器人实际收到的内容，本机从未收到的群历史无法凭空补回。
引用消息按机器人与当前私聊／群聊保存到 `message-references.jsonl`，完整保留正文、发言人、消息索引和可用附件，重启后仍能查找。优先补全本地原文并合并 QQ 推送的引用内容，支持嵌套引用与聊天记录；引用图片会作为图片输入交给模型，已下载的附件优先复用。QQ 未提供且本地没有的内容、已失效的附件会明确标记，不会猜测或阻断本轮正文。仅发送引用而不输入文字也可触发处理，群聊仍遵守 @回复和访问范围设置。
开启「使用会话专属提示词」后，内容替代 QQ Bot 的私聊／群聊默认提示词及预设提示词；关闭则恢复跟随 QQ Bot 默认提示词。
保存仅作用于此会话的后续消息，不重启其他会话；提示词变化或切换预设会开始新上下文，原线程历史保留。任务执行中需等待完成后保存。

全局模型、提示词和权限可以在任务执行期间保存，后续消息使用新设置，当前任务及排队消息继续处理。需要重新连接的设置（例如 QQ 绑定、工作位置、访问范围或群聊触发方式）需等待所有任务完成后保存，避免重启中断回复。没有变化的保存不会重启后台。

「会话设置 → 上下文管理」会显示重置或压缩的进行状态、等待时间及完成／失败结果，关闭设置后仍可在会话页查看。压缩保留聊天记录；重置会中止当前任务、清除原有待处理消息，让重置后收到的消息进入新上下文，并保留会话名称、设置及历史存档。压缩失败或中止后仍可继续聊天或重试。在 QQ 中使用 `/new`、`/reset`、`/clear` 或 `/compact` 也会收到开始与完成反馈。

输入框下方显示最近一次模型统计的当前上下文 Tokens、容量与占比，使用单次请求的输入和输出用量，避免把累计消耗误当作上下文。已有会话可从本机原生记录恢复统计；新会话、容量未知或刚压缩时明确显示等待统计，不按字符数推算。自动压缩默认开启，阈值为容量的 80%，达到阈值后在下一次回复前执行；全局与每个会话均可调整或关闭，默认跟随全局。压缩保留原线程和聊天记录，失败会提示并继续尝试处理消息。
QQ Bot 使用独立的 `codex-home` 运行目录，首次继承本机文件保存的登录，继续使用模型提供商与已安装工具配置。
同一 ChatGPT 账号在桌面端刷新登录后，QQ Bot 下次启动 Codex 工作进程时会同步较新的凭据；机器人自己更新的较新凭据和单独登录的其他账号会保留。
它会显式设置自己的基础指令，关闭全局个性化开发者指令、AGENTS 自动注入及记忆读取与生成；不修改原 Codex 的个性化文件。
QQ Bot 不执行桌面端的外部通知命令，回复由 QQ 消息链路发送。复制到机器人运行目录的配置会移除已失效的 `disable_response_storage` 和 `features.rmcp_client` 设置，原桌面配置保持不变。后台运行日志为每行记录时间和级别；多个插件页面同时打开时共用一个后台连接。
升级前的旧线程可能已经带有人设指令，因此首次继续时会建立干净的新上下文；原线程历史仍保留在 Codex 中。
`/new` 和重置上下文都会保留本会话的模型与专属提示词设置。

QQ API 与访问凭证均使用官方统一域名 `api.bot.qq.com`。
群聊需要将「群聊访问」设为白名单并加入群 OpenID，发起人也需被允许；群聊访问默认关闭，启用后默认仅回复 @机器人的消息。
「最近消息来源」会区分群聊开关关闭、群未加入允许列表和发起人未允许，便于定位收到事件却没有回复的原因。
被动回复按场景限制：私聊 60 分钟内最多 4 次，群聊 5 分钟内最多 5 次；普通消息、文件和一条完整流式回复共用次数。
时效从原消息时间计算，重复推送不延长窗口；原消息过期或次数用完后，优先选取本会话内仍有效的消息 ID，群聊只选取同一发起者的候选，否则使用主动消息。
规则依据 [QQ 官方消息收发文档](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)；主动消息受 QQ 平台权限、用户开关及频控限制。
